Airwolf tester preview: native HackRF acquisition, tunable spectrum, packet and byte inspection, explicit CRC results, and a bundled native decoder. No external Wireshark process or WebAssembly runtime is required.

This update expands native reception and preserves the context needed to inspect and replay selected frames:

- BLE legacy/extended/decision advertising, experimental AuxPtr following, connection following with verified symmetric PHY updates, CTE sample coverage, and one periodic advertising train acquired through SyncInfo/CSA #2. Captured direction and timing constrain reassembly; encrypted data remains opaque.
- Wi-Fi DSSS/CCK at 1–11 Mb/s on supported 2.4 GHz channels, alongside non-HT OFDM at 6–54 Mb/s on supported 2.4/5 GHz channels. Single-stream HT20 adds MCS 0–7, BCC/LDPC, mixed/greenfield, STBC and A-MPDU extraction. Recovery is bounded by received airtime and verified members retain original FCS.
- LTE MIB and scheduled system information through native SI-RNTI/PDSCH reception, ordinary P-RNTI paging and RRC inspection. Cell publication requires two independent PBCH observations. The UI reports when the sampled bandwidth is insufficient for system information.
- Corrected enhanced 802.15.4 headers, short ACKs, Zigbee application values and units. User-supplied Zigbee network/link keys now enable authenticated NWK/APS decryption; OS-protected storage falls back explicitly to session-only when secure persistence is unavailable. Native EnOcean inspection includes teach-in context and supported equipment profiles; ERP2 reception compensates frequency error.
- Experimental native LoRa CSS SF7–12, 125/250/500 kHz, explicit headers, PHY CRC and version-aware LoRaWAN inspection. User-supplied LoRaWAN 1.0.x session and root keys verify MICs, decrypt data frames and decrypt join accepts, in the same protected key storage as Zigbee keys. Public (0x34), private (0x12) and Meshtastic (0x2B) sync words; Meshtastic payloads are encrypted and stay raw. A bundled Wireshark plugin (`wireshark/airwolf.lua`) dissects LoRa and EnOcean PCAP exports and hands public-sync LoRa to Wireshark's LoRaWAN dissector.
- Experimental receive-only CEN DSRC (EN 12253 / EN 12795) at 5.8 GHz: downlink ASK/FM0 500 kb/s and uplink backscatter 2-PSK 250 kb/s on 1.5/2.0 MHz subcarriers, FCS-checked HDLC frames with a tentative LID/MAC/LLC view. **All channels** (the default) decodes channels 1–4 at once from 20 MS/s at 5805 MHz through one shared FFT channelizer; weak uplink frames that miss the FCS by one weak bit decision or an adjacent pair are repaired and marked as such (a clean copy from another timing lane is preferred); a single channel works at 10/16/20 MS/s. Downlink verified live at AutoPASS gantries (288 frames on channels 1 and 2, every FCS valid); live uplink unverified. Application (ISO 14906) and security fields are not decoded. No PCAP export; save SigMF instead.
- Experimental native Nordic Enhanced ShockBurst (dynamic payload) at 250 kb/s, 1 Mb/s and 2 Mb/s on channels 0–125: promiscuous CRC-16 reception with two-frame address confirmation, or a configured 3–5 byte address with CRC-16/CRC-8. Bad-CRC frames are kept for known addresses, single-bit CRC-16 corrections are labelled, and the inspector rechecks the CRC. Validated with generated signals only; over-the-air reception is unverified. No PCAP export (no link type); save SigMF instead.

The IQ timeline retains original samples, groups observed frames into lanes, and links selections to fresh native replay, fields and bytes. Repeated LTE broadcasts match the physical occurrence as well as payload bytes. If a selection does not recover its chosen frame, the inspector does not silently substitute another result. SigMF exports preserve original samples, hashes and bounded receiver context.

Spectrum offers Peak and Mean detectors, channel-centered and full-capture views, channel-width guides, and native SIMD FFT/filter processing. Packet display is virtualized and batched; how many live frames are kept (1,000–20,000, default 2,000) is a remembered setting in the packet list footer. Captures open and save as classic PCAP or PCAPNG; Wi-Fi is saved with a radiotap header that keeps rate, PHY, HT parameters, channel and RSSI, and 802.15.4/Zigbee with a TAP header that keeps the channel; a mixed-protocol export, and **Capture to file** during live reception, write one PCAPNG file with an interface per link type. Multiple HackRF boards can be selected by serial; independent app instances can use separate boards without synchronized capture.

Receive-only macOS checks recovered real BLE advertising, Wi-Fi OFDM, 1 Mb/s DSSS and HT20 MCS 3, and LTE MIB/SIB1/2/3/4/7 and paging. Selected IQ passed native replay and field inspection. Generated fixtures, independent signal generators, public recordings, sanitizer checks and desktop tests provide additional coverage. Live Zigbee was received on a real Zigbee PRO network (channel 25): independently FCS-valid frames in the native worker and a selected frame inspected in the desktop app. Local sweeps did not establish live EnOcean, LoRa or CCK reception, and live GPS is unverified because no satellite reached the test antenna. See `docs/native-validation.md` for evidence and limits.

Windows x64 `.exe`, Debian x64 `.deb`, and macOS Apple Silicon/Intel `.dmg` builds are configured in GitHub Actions. macOS targets 15+; Debian targets Debian 12+ and Ubuntu 24.04+. Windows/macOS radio libraries are bundled; Linux dependencies are installed through apt. These previews are unsigned and macOS builds are not notarized. Follow `USER_GUIDE.md` for USB setup and receiver settings; release installers include SHA-256 checksums.

This is not complete standards support. BLE PAwR, asymmetric PHY changes and seamless connection updates, Wi-Fi HT40, multiple spatial streams, VHT/HE/EHT, complete LTE scheduling/user traffic, decryption outside Zigbee and LoRaWAN 1.0.x, LoRaWAN 1.1 keys and session-key derivation from joins, LoRa SF5/6/implicit headers/FSK/LR-FHSS and continuous rolling IQ remain outstanding. Planned catalog standards do not enable receivers. CI has no HackRF attached; live Windows/Linux interoperability still requires hardware testing.
